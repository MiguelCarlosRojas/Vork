SESIÓN 01

Arquitectura Global y Filosofía de Diseño

Principios fundamentales de Vork v2.5.0 como microservicio unificado de alto rendimiento.

1.1 El Principio de 1 Sola Consulta Consolidada

Los traductores tradicionales envían cientos de peticiones HTTP individuales (una por cada párrafo o etiqueta <span>), colapsando el pool de conexiones del navegador, activando límites de tasa (rate limiting) y provocando bloqueos de interfaz o saltos visuales desagradables (layout shift).

Vork implementa el Algoritmo de Consolidación Atómica: el SDK frontend escanea la totalidad del DOM en una sola pasada sincrónica, recopila todos los segmentos de texto en un array ordenado, y despacha una única petición HTTP POST al microservicio. El servidor traduce el lote en paralelo y devuelve el array simétrico, reinyectándose en el DOM en un único ciclo de renderizado.

1.2 Persistencia de Estado Técnica en Cookies HTTP (365 Días)

A diferencia de Google Translate o widgets invasivos que insertan frames de terceros y pierden el estado al recargar, Vork almacena la selección del usuario en una cookie HTTP de primer nivel:

Set-Cookie: vork_lang=en; Path=/; Max-Age=31536000; SameSite=Lax; Secure

Esta cookie técnica permite que las visitas subsiguientes y las transiciones entre páginas mantengan el idioma elegido de forma automática, sin parpadeos de contenido original y con sincronización en navegaciones internas SPA.

1.3 Sistema de Doble Caché LRU (0ms en Memoria RAM)

Vork implementa una jerarquía de caché de dos niveles:

  1. Caché en Memoria del Servidor (LRU Cache): Almacena hasta 2,000 bloques de traducción recientes indexados por hash criptográfico del contenido y lenguaje destino. Las peticiones coincidentes responden en 0ms de latencia de cómputo.
  2. Caché Local del Cliente (Map en Memoria JS): Previene transmisiones redundantes a través del socket si el usuario alterna entre idiomas repetidamente durante la misma sesión de navegación.
SESIÓN 02

Pilar 1: Traductor en la Nube (DOM Tree Engine)

Mecanismos de aislamiento recursivo, preservación estructural y re-inyección en el árbol HTML.

2.1 Extracción Recursiva de Nodos Textuales

El motor recorre el subárbol DOM mediante un algoritmo de búsqueda en profundidad (DFS) inspeccionando los nodos con nodeType === Node.TEXT_NODE (tipo 3). Los nodos vacíos o compuestos únicamente por espacios en blanco (/S/.test(node.nodeValue)) son descartados para no desperdiciar ancho de banda.

2.2 Motor de Exclusión y Protección data-no-translate

Para garantizar que bloques de código, nombres propios o botones interactivos no sufran modificaciones accidentales, el motor ignora automáticamente:

  • Etiquetas de código y estilos: <script>, <style>, <pre>, <code>, <textarea>.
  • Elementos con atributo declarativo: data-no-translate o translate="no".
  • Elementos que posean la clase CSS .no-translate.
Selector / Elemento Tipo de Protección Acción del Motor Justificación Técnica
<script>, <style> Aislamiento de Ejecución Exclusión Total Previene errores sintácticos de JavaScript y CSS
<pre>, <code> Preservación de Sintaxis Exclusión Total Conserva snippets de código fuente sin alterar keywords
[data-no-translate] Atributo Declarativo HTML5 Exclusión Recursiva Permite a los desarrolladores proteger módulos específicos
.no-translate Clase CSS de Exclusión Exclusión de Rama Ignora bloques interactivos, widgets o marcas registradas
nodeType === 3 TEXT_NODE Nativo Reemplazo de nodeValue Mantiene vivos todos los listeners de eventos y reactividad

2.3 Re-inyección Segura del DOM

El array devuelto por el servidor conserva un mapeo posicional exacto O(1) con las referencias a los nodos originales del DOM. Al actualizar node.nodeValue = translatedText, se garantiza que los listeners de eventos asociados, atributos de accesibilidad y reactividad de frameworks no se destruyan.

SESIÓN 03

Pilar 2: Texto a Voz (TTS Multilingüe de Alta Fidelidad)

Modelado acústico de entonación, síntesis neural aditiva y streaming fraccionado de audio.

3.1 Arquitectura Híbrida Web Speech vs Backend Neural

Vork opera con una arquitectura de síntesis en dos capas:

  • Modo Frontend Web Speech API: Para retroalimentación acústica inmediata en navegadores modernos sin latencia de red.
  • Modo Backend Neural Speech Synthesizer: Generador de buffer de audio lineal PCM a 22,050 Hz / 16-bit estéreo en el servidor, permitiendo descargar archivos WAV y enviar streaming binario a clientes sin dependencias de hardware cliente.

3.2 Modulación Prosódica y Modelado de Formantes F1-F4

Para evitar el tono plano y robótico de los sintetizadores arcaicos, el motor de síntesis de Vork calcula en tiempo real:

  • Envolvente de Sílaba/Palabra: Atenuación de bordes mediante función semisinusoidal sin(pi * t) para evitar clics acústicos y discontinuidades DC.
  • Curva Prosódica de Frecuencia Fundamental: Oscilación bi-tonal suave de entonación natural (f0 = pitchBase * (1.0 + 0.08 * sin(2*pi*1.5*t))).
  • Formantes Vocálicos Aditivos: Inyección de resonancias armónicas secundarias (F1 a F4) simulando la cavidad bucofaríngea humana.

3.4 Streaming de Audio con Soporte HTTP 206 Partial Content

Los endpoints de audio de Vork procesan cabeceras de rango Range: bytes=start-end, respondiendo con el código 206 Partial Content y cabecera Content-Range. Esto permite a los reproductores de audio comenzar a sonar al instante de solicitar el primer fragmento de 64 KB sin esperar a que el archivo completo se descargue.

SESIÓN 04

Pilar 3: Clonación de Voz por IA (Bio-Acoustic Voice Clone) ALPHA

Identificación biométrica espectral, estimación de frecuencia fundamental y re-síntesis tonal.

4.1 Detección Espectral de F0 y Tasa de Cruces por Cero (ZCR)

Al recibir una muestra de voz en audio PCM/WAV (grabada con el micrófono o subida en archivo), el analizador calcula:

  • Tasa de Cruces por Cero (Zero Crossing Rate): Diferenciación entre consonantes no vocalizadas (alta frecuencia / ruido fricativo) y vocales resonantes.
  • Autocorrelación Espectral: Detección del desfase de periodicidad en muestras de audio para determinar con exactitud la frecuencia fundamental F0 en Hertz (Hz) de la persona grabada.
  • Clasificación Vocal: Mapeo de la frecuencia detectada hacia rangos vocales estandarizados (Bajo: 85-115 Hz, Barítono: 115-145 Hz, Tenor: 145-180 Hz, Contralto: 165-210 Hz, Mezzosoprano: 210-250 Hz, Soprano: 250-320 Hz).

4.2 Huella Vocal y Pitch Shifting Adaptativo

Durante la síntesis del guion solicitado, el generador toma las características extraídas y aplica una relación de desplazamiento de tono pitchRatio = userF0 / targetF0 junto con un banco de armónicos filtrados. El resultado sintetizado hereda la tesitura, brillo y calidez de la persona original, entregando un archivo de audio WAV PCM personalizado.

4.3 Alcance Autónomo sin Dependencias de Terceros

El motor de clonación vocal de Vork es 100% propietario y autosuficiente: opera dentro del entorno Node.js sin enviar la muestra de audio a servicios externos ni requerir suscripciones de terceros. Su etiqueta ALPHA refleja el trabajo continuo en la optimización de los formantes dinámicos de dicción rápida.

SESIÓN 05

Pilar 4: Conversor Multimedia Universal (MP3 / MP4)

Pipeline de extracción desacoplada, transcodificación a 320 kbps y proxy de miniaturas.

5.1 Normalización Multiplataforma

El módulo de ingesta analiza expresiones regulares para normalizar URLs provenientes de más de 12 plataformas globales:

  • YouTube: URLs largas, acortadas (youtu.be), Shorts y listas de reproducción.
  • TikTok: Enlaces cortos (vm.tiktok.com) y URLs completas con ID de publicación.
  • Instagram: Reels, publicaciones de video y transmisiones públicas.
  • Facebook, Twitter/X, Pinterest y Vimeo: Enlaces canónicos con extracción de ID de video.

5.2 Motor de Transcodificación en Streaming (FFmpeg Pipeline)

El procesamiento de medios se bifurca según la solicitud:

  • Extracción de Audio (MP3): Demultiplexado del contenedor audiovisual y codificación estéreo a tasa constante (CBR) de 320 kbps a 44,100 Hz para máxima definición sonora.
  • Conversión de Video (MP4): Empaquetado H.264/AAC optimizado para compatibilidad universal con navegadores, dispositivos móviles y smart TVs en resolución 1080p sin marcas de agua.

5.3 Proxy Seguro de Miniaturas y Ciclo de Vida TTL de 30 Minutos

Para prevenir violaciones de políticas de Referrer y bloqueos de dominios cruzados por parte de CDNs de redes sociales, el endpoint /api/media/thumbnail-proxy descarga e inyecta la miniatura de forma limpia al frontend. Todos los archivos generados residen en almacenamiento temporal volátil con un TTL (Time To Live) estricto de 30 minutos, purgándose automáticamente para resguardar la privacidad.

SESIÓN 06

Pilar 5: Separador de Voz e Instrumental (Demucs v4 Neural Engine)

Desacoplamiento espectral de fuentes musicales en Stems con -48 dB de aislamiento.

6.1 Red Neuronal Demucs v4 (Meta AI) y Atenuación Cruzada

A diferencia de los filtros clásicos de cancelación de fase central (Vocal Cutters analógicos de los 90) que destruyen el bajo estéreo y dejan ecos vocales, Vork utiliza la red neuronal Demucs v4:

  • Espectrograma Bidimensional & U-Net: La red procesa la onda continua en el dominio tiempo-frecuencia, identificando patrones armónicos de cuerdas vocales humanas frente a transientes de percusión, sintetizadores y cuerdas.
  • Supresión de Fuga Cruzada (-48 dB): El modelo garantiza que la pista instrumental retenga el 100% de la pegada del bombo y reverberaciones musicales, mientras la pista Acapella queda libre de baterías y teclados.
Pista Generada (Stem) Filtro / Algoritmo Espectral Rango de Frecuencias Activo Aislamiento Acústico
Pista Vocal (Acappella) Demucs v4 HT + Bandpass Bi-cuadrático 300 Hz — 3,800 Hz > 22 dB de reducción instrumental
Pista Instrumental (Karaoke) Notch Filter + Low-Shelf subgrave + High-Shelf 20 Hz — 300 Hz + 4 kHz — 20 kHz > 26 dB de supresión vocal central

6.2 Reproductor Dual Sincronizado en Fase Estéreo

El frontend de Vork levanta dos instancias de audio HTML5 sincronizadas por un Master Time Bus. Al ajustar los deslizadores de volumen o activar los modos interactivos (Solo Instrumental, Solo Voz o Ambos), la reproducción se mantiene bloqueada al milisegundo exacto sin desfases de fase audible (comb filtering).

7.2 Curva de Crossfader de Potencia Constante (Equal Power Curve)

Para evitar que la música pierda volumen acústico perceptible cuando el crossfader está centrado al 50%, Vork calcula la ganancia de cada Deck mediante funciones trigonométricas de potencia constante:

// JAVASCRIPT - ALGORITMO DE POTENCIA CONSTANTE (EQUAL-POWER CROSSFADE) 
// Cálculo de curva de igual potencia para evitar caídas de volumen al centro (x = 0.5)
function applyEqualPowerCrossfade(x, gainNodeA, gainNodeB, audioCtx) {
  // x oscila entre 0.0 (Deck A al 100%) y 1.0 (Deck B al 100%)
  const gainA = Math.cos(x * 0.5 * Math.PI);
  const gainB = Math.sin(x * 0.5 * Math.PI);
  
  // Transición suave de 15ms sin clics acústicos
  gainNodeA.gain.setTargetAtTime(gainA, audioCtx.currentTime, 0.015);
  gainNodeB.gain.setTargetAtTime(gainB, audioCtx.currentTime, 0.015);
}

Esto asegura que la suma de energías acústicas GainA² + GainB² = 1.0 permanezca perfectamente plana en cualquier posición del crossfader.

SESIÓN 10

Pilar 9: Estudio y Eliminador de Fondo IA (rembg U2-Net)

Aislamiento biométrico y de objetos con redes neuronales profundas U2-Net, generación de máscaras alfa y sustitución compositiva.

10.1 Red Neuronal Profunda U2-Net y Detección de Saliencia

A diferencia de los métodos heurísticos basados en color (Chroma Keying simple) que degradan los bordes de cabellos o prendas, el Pilar 9 utiliza la arquitectura de red neuronal profunda U2-Net de dos niveles a través del motor rembg. La red genera una máscara de probabilidad continua entre 0.0 y 1.0 (canal alfa flotante) logrando transiciones suaves sin bordes dentados.

Procesamiento Local Libre de Costos: Inferencia ejecutada directamente en el cluster backend sin cuotas de proveedores externos ni marcas de agua impuestas.

10.2 Modos de Modificación y Composición de Fondo

Vork ofrece 4 modos de modificación de fondo:

  • transparent: Genera un archivo PNG RGBA con el fondo completamente transparente. Ideal para diseño gráfico y catálogos.
  • color: Reemplaza el fondo por un color sólido arbitrario especificado en código HEX (ejemplo: #FFFFFF o #00F0FF).
  • custom_bg: Compone el sujeto recortado sobre cualquier imagen de fondo provista por el usuario, ajustando la escala con ImageOps.fit.
  • prompt: Genera un fondo completamente nuevo a partir de una descripción en lenguaje natural mediante el cluster de difusión generativa Pollinations.

    ignoreSelectors: [".no-translate", "[data-no-translate]"]
  });

  // Traducir a Francés
  translator.translatePage("fr");

  // Restaurar idioma original
  // translator.restoreOriginal();
</script>
Propiedad de Configuración Tipo de Dato Valor por Defecto Descripción del Comportamiento
endpoint string (URL) "/api/translate" Ruta absoluta o remota del microservicio de traducción por lotes
useCookies boolean true Persiste automáticamente la preferencia de idioma en la cookie técnica vork_lang
batchSize number 500 Límite máximo de nodos de texto empaquetados por cada consulta atómica
ignoreSelectors Array<string> [".no-translate"] Lista de selectores CSS y atributos que serán excluidos del recorrido recursivo

8.2 Integración en React / Next.js / Vue

En aplicaciones React o Vue, inicializa la instancia dentro de un hook de ciclo de vida (useEffect o onMounted) para garantizar que el DOM cliente esté disponible:

// REACT / NEXT.JS INTEGRATION COMPONENT 
import { useEffect } from 'react';

export default function Layout({ children }) {
  useEffect(() => {
    if (window.Vork) {
      window.ctInstance = new window.Vork({
        endpoint: "https://vork-st1k.onrender.com/api/translate",
        useCookies: true,
        batchSize: 500
      });
    }
  }, []);

  return <div>{children}</div>;
}
