Preguntas Frecuentes de los 9 Pilares (FAQ)

¿Por qué la primera petición puede tardar entre 25 y 35 segundos?

El microservicio se ejecuta en el tier en la nube de Render. Si el servidor no recibe tráfico durante 15 minutos continuos, entra en modo reposo automático (sleep). La primera solicitud despierta la máquina virtual ("cold start") en aproximadamente 25 a 35 segundos. Tras reactivarse, todas las consultas responden de inmediato con latencias ultrarrápidas de 150 a 300 ms (o 0 ms si provienen del caché en memoria RAM).

PILAR 01 // TRADUCTOR EN LA NUBE

¿Cómo optimiza Vork el consumo de red en mi navegador?

A diferencia de scripts tradicionales que disparan cientos de peticiones HTTP por cada párrafo o etiqueta, el SDK de Vork recorre el árbol DOM mediante TreeWalker, agrupa todos los textos visibles únicos en un solo arreglo JSON (texts: [...]) y realiza una única solicitud HTTP consolidada hacia POST /api/translate.

¿Cómo funciona la memoria de traducción en caché y la persistencia?

Vork opera con cero uso de localStorage. Utiliza una memoria caché activa en RAM durante la sesión (Map) tanto en el navegador como en el servidor (caché LRU de hasta 10,000 entradas), respondiendo en 0 ms ante textos repetidos. Para recordar el idioma entre páginas y visitas, emplea la cookie técnica vork_lang con vigencia de 365 días (SameSite=Lax).

PILAR 02 // TEXTO A VOZ (TTS)

¿Qué opciones de síntesis y voces ofrece el Estudio TTS?

Ofrece un motor híbrido: síntesis instantánea en navegador mediante Web Speech API con modulación de velocidad (rate) y tono (pitch), y un catálogo de 24 voces humanas neuronales en backend (accesibles en GET /api/tts/voices). Admite generación directa y streaming con descarga forzada en formato binario .wav o .mp3.

PILAR 03 // CLONACIÓN DE VOZ CON IA

¿Cómo funciona la clonación y qué tipo de muestra requiere?

Puedes grabar directamente tu voz con el micrófono del dispositivo (mediante navigator.mediaDevices.getUserMedia) o cargar un archivo de audio (.wav, .mp3, .ogg, .m4a). El motor bio-acústico extrae los formantes y la frecuencia fundamental (F0) para recrear tu timbre único al sintetizar cualquier guion escrito, permitiendo descargar el archivo de audio generado.

PILAR 04 // CONVERSOR MULTIMEDIA (MP3 / MP4)

¿Qué plataformas y calidades de conversión están soportadas?

El motor procesa enlaces de YouTube, TikTok (sin marcas de agua), Instagram Reels, Facebook, Twitter/X, Pinterest y archivos multimedia directos. Permite extraer Audio en MP3 (320 kbps, 256 kbps, 192 kbps y 128 kbps) o Video en MP4 (1080p Full HD, 720p HD, 480p y 360p). Admite modo individual o conversión masiva por lotes de hasta 10 enlaces simultáneos con streaming binario y descarga directa.

[ 02 // DIAGNÓSTICO_Y_RESOLUCIÓN ]

Resolución de Problemas Reales (Troubleshooting)

Error HTTP 400: Parámetros de Idioma en Traducción

El endpoint POST /api/translate admite tanto el alias estándar to como targetLanguage (ej: "to": "en" o "targetLanguage": "fr"). Para el texto, envía text: "cadena" o el arreglo por lotes texts: ["cadena 1", "cadena 2"].

Error en Síntesis TTS: "Texto requerido o voz no válida"

En POST /api/tts debes enviar un objeto JSON con text (máximo 5000 caracteres por solicitud) y opcionalmente lang o voice. Consulta las voces disponibles en tiempo real llamando a GET /api/tts/voices.

Error en Clonación de Voz: "Muestra de audio requerida"

Asegúrate de proporcionar permisos de micrófono en el navegador o subir un archivo de audio legible (mínimo 3 segundos y máximo 10 MB). El endpoint POST /api/voice-clone procesa la muestra mediante multipart/form-data o JSON con sampleBase64.

Error en Conversor: "URL no soportada o contenido privado"

Verifica que el enlace pertenezca a una de las plataformas compatibles (YouTube, TikTok, Instagram, Facebook, Twitter/X, Pinterest) y que el contenido sea público. Los videos configurados como privados o con restricciones de edad de terceros requieren acceso autenticado no disponible en la API pública.

Consultas CORS desde otros dominios o aplicaciones móviles

Vork cuenta con CORS universal abierto (Access-Control-Allow-Origin: *) y gestiona automáticamente las peticiones de verificación OPTIONS devolviendo estado 204 No Content.
